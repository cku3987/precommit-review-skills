# precommit-review-skills ガイド

[precommit-review-skills](https://github.com/cku3987/precommit-review-skills) は、Git と SVN のコミット前レビュー用の独立した Codex Agent Skill 集です。リリースはリポジトリ単位で共通ですが、各スキルは個別にインストールして呼び出します。既存の `svn-precommit-review` の名前と `SKILL.md` は維持されるため、既存のインストール名を変更しないでください。

- [SVN スキル](../svn-precommit-review/SKILL.md)
- [Git スキル](../git-precommit-review/SKILL.md)
- [Git 詳細ガイド](git-precommit-review-guide.md)

## Git

`git-precommit-review` はレビュー報告とコミットメッセージを韓国語で作成します。

- 標準の呼び出しではレビューとともに、必要性が確認された安全な新規ファイルを自動でステージングします。無視対象、生成物、秘密情報を含むファイルは除外します。
- 読み取り専用を明示すると、一切書き込みません。
- コミット依頼時はレビュー済みの追跡ファイルの変更を準備しますが、既存の部分ステージングは保持します。範囲指定のコミットには無関係なステージ済み変更を含めません。
- 実際のコミットには範囲とメッセージへの一度の最終確認が必要です。`push` は別途依頼された場合のみ実行します。

標準の呼び出し、韓国語のコミット依頼（`커밋해줘`）、明示的な読み取り専用の例:

```text
$git-precommit-review
$git-precommit-review 변경사항을 검토하고 커밋해줘.
$git-precommit-review 現在の Git 変更を読み取り専用で確認して。一切書き込まないで。
```

## SVN

`svn-precommit-review` は、SVN/TortoiseSVN のコミット直前に変更を確認し、韓国語のコミットメッセージを作成する Codex Agent Skill です。標準の呼び出しではレビューと、安全基準を満たす必須の新規ファイルの自動 `svn add` を行います。実際のコミットにはユーザーの依頼と範囲・メッセージへの一度の最終承認が必要で、承認範囲だけをコミットします。

### インストール

```text
%USERPROFILE%\.codex\skills\svn-precommit-review\SKILL.md
```

または:

```text
<project-root>\.agents\skills\svn-precommit-review\SKILL.md
```

このリポジトリの `svn-precommit-review/SKILL.md` をコピーしてください。

### 使い方

標準のレビューと必須ファイルの準備（単なる「確認して」や `검토해줘` も同じ）:

```text
$svn-precommit-review
```

読み取り専用の確認:

```text
$svn-precommit-review 現在の SVN 変更を読み取り専用で確認するだけにして。svn add/delete/commit は実行しないで。
```

レビューとコミットを依頼:

```text
$svn-precommit-review <SVN_WORKING_COPY> の変更を確認してコミットして。
```

コミットを依頼した場合、対象・除外範囲、準備済みの add/delete、残るリスクとメッセージを確認し、最終質問に一度返答します。「コミットして」や `커밋해줘` で十分で、`CLI` という指定は不要です。

```text
네, 진행해
```

### 動作

- `svn status --xml`、リモート状態、内容 diff、property diff を確認します。
- 生成物、IDE/ユーザー固有ファイル、ログ、ローカル設定、秘密情報、競合、欠落ファイル、テスト不足を確認します。
- 標準のレビューでは、追跡済みファイルの参照や確認した変更から必要性が明確な未追跡のソース、プロジェクト、リソース、ローカル専用でない設定ファイルを必ず自動 `svn add` します。基準を満たす場合は推奨だけで終わりません。
- 読み取り専用、レビューのみ、メッセージのみ、変更禁止の明示があれば一切書き込みません。通常の「確認して」は標準の準備を含みます。
- add コマンドの成功と `svn status` の `A` 状態の両方を確認して初めて完了とします。完了した追加は変更ファイルの要約に記載し、未解決の警告には残しません。
- コード上のリスクが残っていても、独立した安全な add は実行できます。そのリスクは引き続き報告し、add でコードが修正されたとは扱いません。
- `bin`、`obj`、生成物、IDE/ユーザー固有ファイル、ログ、一時ファイル、キャッシュ、ローカル設定、アーカイブ、ダンプ、バックアップ、スクリーンショット、無視対象、`.env`、秘密情報の可能性があるファイル、曖昧なファイルは add しません。ディレクトリは配下をすべて調べ、全体が安全な場合だけ追加し、それ以外は安全な個別パスだけを追加します。
- 削除候補を含めるよう依頼された場合、確認済みのクリーンな versioned ローカルパスだけを削除予約できます。
- 競合、ローカル修正、switched、external、lock、意図不明のパスは削除予約しません。
- 実際のコミットには依頼と正確な範囲・メッセージへの最終承認が必要です。同じ範囲・内容への以前の承認を引き継ぎ、直前に status と内容・property diff を再確認します。範囲・内容の実質的な変更やブロック状態の変化がある場合だけ再レビューして承認を求めます。
- TortoiseSVN での手動コミットを明示した場合は、CLI コミットもその確認質問もせず、レビューとチェックリストで終了します。読み取り専用でなければ標準の安全な準備は行います。
- 広範囲の `svn add`、`svn delete`、`svn commit` は使用しません。

実行中の案内、レビュー、コミットメッセージ、結果はすべて韓国語で記述します。要約は変更意図ごとにまとめ、固定の箇条書き数や冗長な説明を求めません。以前のテストは実際の証拠があり、レビュー対象の内容が変わっていない場合だけ再利用し、過去の結果で今回は再実行していないと明記します。

### 韓国語コミットメッセージ

CLI コミットでは作業コピーの外に一意の一時メッセージファイルを BOM なし UTF-8・LF で作成し、`--file` と `--encoding UTF-8` を使用します。

```powershell
svn commit --file <message-file> --encoding UTF-8 <approved-paths>
```

一時ファイルは試行のたびに削除し、残っていないことを確認します。可能ならコミット出力から特定した実際のリビジョンの XML ログメッセージを原文と厳密に比較します。保存済みメッセージの韓国語が壊れていた場合、再コミットや revision property の変更は行わず、検証失敗として報告します。
