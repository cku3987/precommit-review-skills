# Руководство svn-precommit-review

`svn-precommit-review` проверяет рабочую копию SVN/TortoiseSVN перед коммитом и создаёт сообщение коммита на корейском языке как навык Codex Agent. По умолчанию вызов выполняет проверку и автоматический `svn add` необходимых новых файлов, отвечающих критериям безопасности. Сам коммит требует запроса пользователя и одного финального подтверждения области и сообщения; коммитится только одобренная область.

## Установка

```text
%USERPROFILE%\.codex\skills\svn-precommit-review\SKILL.md
```

или:

```text
<project-root>\.agents\skills\svn-precommit-review\SKILL.md
```

Скопируйте `svn-precommit-review/SKILL.md` из этого репозитория в выбранное место.

## Использование

Обычная проверка и подготовка необходимых файлов (простой запрос «проверь» или `검토해줘` работает так же):

```text
$svn-precommit-review
```

Проверка только для чтения:

```text
$svn-precommit-review Только проверь текущие изменения SVN в режиме чтения. Не выполняй svn add/delete/commit.
```

Запрос проверки и коммита:

```text
$svn-precommit-review Проверь изменения в <SVN_WORKING_COPY> и выполни коммит.
```

Если коммит запрошен, проверьте включённые и исключённые пути, подготовленные add/delete, оставшиеся риски и сообщение, затем один раз ответьте на финальный вопрос. Достаточно «выполни коммит» или `커밋해줘`; слово `CLI` не требуется.

```text
네, 진행해
```

## Поведение

- Проверяются `svn status --xml`, состояние удалённого репозитория, content diff и property diff.
- Проверяются сгенерированные файлы, IDE/пользовательские файлы, логи, локальная конфигурация, секреты, конфликты, отсутствующие файлы и недостаточная проверка тестами.
- При обычной проверке автоматически и обязательно выполняется `svn add` неотслеживаемых исходников, файлов проектов, ресурсов и конфигурации не только для локального использования, если их необходимость подтверждена ссылками из отслеживаемых файлов или проверенными изменениями. При выполнении критериев одной рекомендации недостаточно.
- Явные запросы «только чтение», «только проверка», «только сообщение» или «без изменений» запрещают любые записи. Обычное «проверь» включает подготовку по умолчанию.
- Добавление считается завершённым только после успешной команды add и подтверждения состояния `A` через `svn status`. Завершённые добавления указываются в сводке файлов, а не среди нерешённых предупреждений.
- Независимое безопасное добавление допустимо даже при оставшемся риске в коде. Риск продолжает указываться; add не считается исправлением кода.
- Не добавляются `bin`, `obj`, сгенерированные файлы, файлы IDE/пользователя, логи, временные файлы, кэш, локальные настройки, архивы, дампы, резервные копии, снимки экрана, игнорируемые файлы, `.env`, файлы с возможными секретами и неоднозначные файлы. Перед добавлением каталога рекурсивно проверяется всё содержимое: если оно не полностью безопасно, добавляются только конкретные безопасные пути.
- По запросу включить проверенные кандидаты на удаление удаление планируется только для чистых versioned локальных путей.
- Не удаляются локально изменённые, конфликтующие, switched, external, locked или неоднозначные пути.
- Сам коммит требует запроса и финального одобрения точной области и сообщения. Предыдущее одобрение той же области и содержимого сохраняется; перед коммитом повторно проверяются status, diff содержимого и свойств. Повторная проверка и новое подтверждение нужны только при существенном изменении области, содержимого или изменении блокирующего состояния.
- При явном выборе ручного коммита в TortoiseSVN работа заканчивается проверкой и чек-листом, без CLI-коммита и вопроса о нём. Без требования режима чтения обычная безопасная подготовка всё равно выполняется.
- Широкие `svn add`, `svn delete` и `svn commit` не используются.

Все пояснения в ходе работы, проверка, сообщение коммита и результаты пишутся только на корейском языке. Сводки группируются по цели изменений, без фиксированного числа пунктов и избыточных подробностей. Прежние тесты учитываются только при наличии реальных свидетельств, применимых к неизменённому проверяемому содержимому; они помечаются как предыдущие результаты, не запущенные повторно.

## Корейское сообщение коммита

Для CLI-коммита вне рабочей копии создаётся уникальный временный файл сообщения в UTF-8 без BOM с окончаниями строк LF; используются `--file` и `--encoding UTF-8`:

```powershell
svn commit --file <message-file> --encoding UTF-8 <approved-paths>
```

После каждой попытки временный файл удаляется и проверяется его отсутствие. Если доступ к репозиторию позволяет, сообщение XML-журнала фактической ревизии, определённой по выводу команды коммита, посимвольно сравнивается с исходным. Если сохранённый корейский текст повреждён, навык сообщает о сбое проверки кодировки и не повторяет коммит и не меняет revision property.
